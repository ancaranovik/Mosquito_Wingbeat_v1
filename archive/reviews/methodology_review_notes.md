# Independent methodology review

These are proposed design choices and acceptance targets, not achieved results or claims from the literature.

## Highest-priority corrections

1. Define the core as **closed-set species classification conditional on an eligible mosquito recording**. A species softmax will assign ambient speech, fans, or silence to a species; this is not mosquito-presence detection. A simple clipping/low-level quality status may suppress unusable input, but it is not a validated mosquito detector. A background class or detector requires its own suitable negative dataset and evaluation and should not silently become a second mandatory project.
2. Live microphone inference need not imply access to captive live specimens. Stored-audio replay establishes numerical parity; physical playback through the microphone establishes acquisition-to-inference integration. Both must be clearly separated from live flying-mosquito accuracy. If genuine live recordings are available, include them only with a credible recording/label protocol. This distinction removes a major hidden 12-week dependency.
3. Freeze one dataset/subset, one compact architecture, and one native feature baseline early. The existing proposal leaves almost every engineering choice open while assigning five weeks to a five-condition optional synthesis study. The core should occupy approximately ten weeks, with the remaining weeks protected for analysis/reporting/contingency. Advanced work can start early only after the measured core acceptance gate passes.
4. Replace universal claims of 'independent data' with the independence actually supported by metadata. Source-recording disjointness does not prove individual or session disjointness when IDs are missing.
5. Correct 'presence probabilities': ordinary softmax/sigmoid scores need not be calibrated biological probabilities. Call them class scores or model outputs unless calibration is evaluated.

## A sufficiently specified, affordable DSP baseline

An initial proposal could use mono 16 kHz, fixed PCM amplitude scaling, one-second analysis windows updated every 0.5 s, 512-sample Hann STFT windows, 256-sample hops, no centered padding, squared magnitude, 40 Mel bands over an initially chosen 200–4000 Hz interval, a fixed log floor, and training-fitted feature normalization. This produces 61 frames and a 40 by 61 by 1 tensor. At 16 kHz the FFT bin spacing is 31.25 Hz and the analysis frame is 32 ms. These are engineering starting values to inspect against training spectra and benchmark on the board; they are not a literature-derived optimum, and FFT bin spacing is not the same as effective spectral resolving power.

The frequency interval should be described as a compact working band, not a universally sufficient species band. Inspect training spectra and eligible signal coverage before fixing it. Anti-aliased resampling and channel selection must be identical across training and firmware. A higher native acquisition rate, if required by the microphone, adds explicit resampling cost. The proposal can freeze the baseline after one planned training/validation review rather than leave parameter search open indefinitely.

Log-Mel means logarithm of Mel-filterbank energies; MFE is often an implementation name for the filterbank-energy step and is not necessarily a different representation. MFCC applies a DCT to log-Mel energies. These are candidates, not a justified ranking. One optional comparison with cropped log-power STFT (or a longer 1024-point window at the same sampling rate) is enough; do not compare four feature families and RGB image rendering within the mandatory schedule. A native one-channel tensor avoids image resizing/colormapping and large vision backbones but is not claimed automatically more accurate.

Avoid per-window RMS/peak normalization if absolute input-level sensitivity is being studied: it can erase that experimental factor. Fixed digital scaling plus training-only feature statistics preserves it. Document microphone gain/AGC configuration. A one-second int16 mono ring buffer is 32,000 bytes; any second buffer, FFT scratch, Mel features, tensor arena, task stacks, driver buffers, and model allocation must also be included in RAM reporting. This calculation does not establish that the whole system fits.

Use a small Conv/ReLU/pooling family with global average pooling and a K-way softmax; full integer operator support and memory allocation must be smoke-tested on the actual ESP32-S3 by Week 2. An approximate 50k-parameter or 250 KiB model-file design ceiling can be declared if desired, but it is a chosen engineering budget, not a datasheet guarantee. Parameters/file size do not predict activation-memory use by themselves.

## Leakage-safe evaluation

- Audit acquisition, label hierarchy, sex, class counts, licenses, duration, sample rate, duplicates, and available group metadata before choosing the final species set. Do not treat an unspecified Anopheles label as a species-level class.
- Form groups using all known individual/session/source links; keep the highest available shared biological/acquisition unit together in train, validation, and test. A source appearing in multiple public datasets must retain the same group. Hash/examine duplicates before pooling.
- Use a fixed grouped partition with usable class coverage (approximate proportions are subordinate to group/class feasibility). Publish recording/group counts as well as window counts. Group imbalance may require fewer species, not window-wise random splitting.
- Window, augment, and synthesize only within partitions. Fit normalization, selection rules, quantizer calibration, and class balancing from training data; use validation for model and decision thresholds. No test data in representative INT8 calibration.
- Keep the final test manifest sealed through model/DSP selection. Run clean and prespecified perturbed test conditions after freezing the experiment; no subsequent tuning based on results. 'Run once' means no iterative decision-making on test results, not that a corrected metric script can never rerun.
- Report per-class precision/recall/F1, macro-F1, balanced accuracy, confusion matrix, and majority-class reference. Long recordings should not gain arbitrary influence simply by yielding more overlapping windows; include recording-level summaries or equal group weighting. If confidence intervals are offered, resample source groups, not individual windows. Repeated training seeds estimate optimization variability, not new biological test samples.
- Baseline adaptation to a safer split is a reproduction of the method, not an exact reproduction of the original reported score. Give the reason scores are not directly comparable.

## Quantization and real-time verification

Compare identical selected models as native FP32, desktop exported FP32, desktop INT8, and MCU INT8 so conversion, quantization, and deployment disagreement are not conflated. Full integer quantization uses a representative training subset spanning classes/levels. It does not require every DSP operation to use fixed point: float DSP plus INT8 neural inference is a valid scope. Quantization-aware training is a fallback only after calibration and architecture simplification are checked.

Two parity levels matter: (a) identical feature tensors into desktop/MCU inference; (b) identical PCM into Python/MCU preprocessing and inference. Report maximum/mean feature/output deviation and class agreement on a fixed golden set covering each class, low level, clipping, and boundary conditions. Exact bitwise equality is not generally required, but any numerical tolerance must be justified before final evaluation; do not tune thresholds to hide an implementation mismatch.

Measure model-file bytes, full firmware flash, tensor-arena bytes, total peak/minimum-free runtime RAM, internal SRAM versus PSRAM, CPU clock, microphone/acquisition settings, runtime version and optimization settings. Tensor arena alone is not total RAM. Measure DSP time, model time, and end-of-window-to-output time separately (median, 95th percentile, maximum); count missed deadlines, buffer overflow, dropped samples, and stale results under the intended logging/output load.

For one-second windows every 0.5 s, the sustainable deadline is **0.5 s**, not one second. Conventional real-time factor T_processing/1 s can be below one while still missing the update schedule. State both it and the stronger requirement T_pipeline < update interval, with the measured maximum and margin. Initial context accumulation and buffering contribute to decision delay and must not be hidden in inference time.

A core acceptance gate can require: all operators execute on the selected board; the held-out closed-set assessment and FP32/INT8 comparison are completed; a prespecified engineering degradation target (e.g., no more than 3 macro-F1 percentage points on validation) is met or explicitly reported as unmet; PCM/feature parity checks pass; at least ten minutes of acquisition/DSP/inference run with no lost samples, overflow, or missed update deadlines under the tested setup; peak RAM/flash fit with stated margin; and the microphone-to-local-prediction demonstration is complete. Hardware targets are proposed tests, not guaranteed results. Statistical accuracy should not be invented to make a project appear successful; an honestly characterized limitation can still be an academically useful completed study.

## A bounded, interpretable extension

Use **two training conditions** first: previous-style linear mixing rebuilt with safe source partitions, and a conservative revised generator. Source partition safety must be identical in both: leakage must never be an ablation variable. If the old implementation is unavailable, call it a documented reconstruction rather than exact reproduction.

Restrict mixtures to one or two distinct species initially. Keep the number of training examples, species prevalence/cardinality, architecture, preprocessing, optimizer, training budget, validation rule, and evaluation clips matched. If training randomness can change the result, use the same three seeds for both conditions, or explicitly label a single-seed exploratory comparison. A five-condition ablation plus curriculum training, external swarms, and embedded multi-label deployment is too much to promise.

Use active source segments, temporal offsets, controlled overlap duration and relative active RMS, real noise recordings, and common headroom scaling that avoids clipping. Do not claim the sum is an acoustic swarm simulator. Source count is the number of snippets, not validated mosquito count. Selected source recordings often already contain acquisition/background noise; a ratio computed from source-recording RMS is a **nominal recording-to-added-noise ratio**, not measured clean-wingbeat SNR. Source activity screening must not be only an RMS threshold because loud noise can pass it. Define an inexpensive criterion and manually audit a small training sample; freeze it and report retained/rejected coverage by species. Extremely weak/masked sources can be labeled as intended source contributions but cannot be assumed acoustically detectable.

Use K independent sigmoid outputs with binary cross-entropy. Choose a global threshold on validation first; per-class thresholds are optional and unstable with sparse validation positives. Apply the same threshold-selection procedure independently to each model. Include per-species AP/precision-recall and micro/macro-F1, label cardinality and failure cases; exact-match accuracy is optional and should not dominate.

All methods must face the same held-out-source mixture suite plus a prespecified shifted-noise/level condition. Evaluating each generator on its own test distribution confounds the training comparison. Physical playback/re-recording uses separate development recordings for any setup decisions, and final held-out clips/settings for transfer checks. It demonstrates a speaker-room-microphone channel; it is not genuine live-swarm validation, and known playback content does not guarantee every source survives masking/channel losses at the microphone.

The three approximately 12-second genuine swarm recordings must remain sealed until the end. Do not train, tune, calibrate, select thresholds, or choose generator settings with them. Report clip-level/time-resolved outputs beside available biological inventory and uncertainty. Do not treat overlapping windows as independent real samples or claim per-window species sensitivity when acoustic activity is unknown. They can illustrate plausible or implausible responses, but cannot establish statistically reliable synthetic-to-real improvement.

## Suggested workload

Weeks 1–2: dataset/split/labels, baseline reproduction, board/microphone/full-operator smoke tests in parallel. Weeks 3–4: fixed DSP and tiny model; validation and INT8 conversion. Weeks 5–6: PCM/feature parity and integration with buffered acquisition. Weeks 7–8: continuous inference, runtime profiling, controlled robustness, remedy core failures. Weeks 9–10: freeze configuration, held-out evaluation, resource/reliability measurements, failure analysis and core demonstration. Weeks 11–12: report/reproducibility/demo and contingency. A two-condition swarm experiment may use remaining time only if the core gate has already passed; its deployment/playback/case study can be tiered optional deliverables or explicitly future work. No assumption that the student must finish the core in six weeks.
